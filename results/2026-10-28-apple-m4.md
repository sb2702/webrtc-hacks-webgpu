- Chrome 156, macOS, WebGPU adapter `apple / metal-3 / Apple M4`, cross-origin isolated, WebNN flag enabled
- Mode `transcode`, order `sequential`, 1 warm-up + 5 timed runs per pipeline, 192 frames per run
- Machine checked idle (it also serves intermittent background jobs; runs taken while those were active were discarded)
- Recorded with the harness in this repo before JSON export existed, so this file is a transcription of the
  run log rather than a raw report. Re-run with `npm run bench -- --sample 360p` and
  `npm run bench -- --sample 720p` to get JSON reports.

| WebNN — CPU, fp32 | 266 | no |

The `npu` / `gpu` hints give identical outputs and timings; fp16 vs fp32
decides whether Core ML uses the Neural Engine.

## Correctness on this machine

- `/test.html`: WebGPU 8.6e-6, WebGL 9.8e-6, WebNN cpu / gpu / npu ≤8.6e-6 max
  abs error vs TFLite (fp32).
- Check outputs: all pipelines agreed with ours-WebGPU on ≥99.5% of pixels.

## Our WebGPU port: GPU time per layer type (`/profile.html`)

Before the pool fix: 7.13 ms per frame, of which global average pool 5.78 ms
(10 dispatches), conv 0.69 ms (43), depthwise 0.30 ms (11), add 0.20 ms (14),
other 0.16 ms (14). After: pool 0.24 ms. Timestamp totals are an upper bound
(one pass per dispatch) and vary with GPU clocks.
